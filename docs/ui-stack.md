## Components and where they came from

**Generated by the shadcn CLI** (`npx shadcn@latest add …`) and then themed by us:
`avatar`, `breadcrumb`, `checkbox`, `command`, `dialog`, `dropdown-menu`, `kbd`, `label`, `popover`, `scroll-area`, `select-menu` (shadcn `select`, renamed so it didn't overwrite ours), `separator`, `sheet`, `skeleton`, `sonner`, `switch`, `table`, `tabs`, `textarea`, `tooltip`.

> Gotcha: the shadcn CLI in this repo once wrote `import { cn } from "cn"` and installed an unrelated npm package called `cn`. After any `shadcn add`, check for `from "cn"` and change it to `@/lib/utils`, then uninstall `cn` if it appeared.

**Rewritten by us in shadcn style** (same props as the old TestFlow components, so existing pages kept working):
`button` (adds `loading`, `asChild`, legacy variant names), `input` (label/error/hint), `card` (`interactive`, `selected`, `CardArrow`), `badge`, `modal` (built on Dialog; `closeOnBackdrop` / `closeOnEscape` default off), `select` (our props, Radix select inside).

**Built by us** (no external source):

| Area | Files |
|---|---|
| UI primitives | `ui/alert`, `ui/data-table`, `ui/multi-select`, `ui/search-input`, `ui/segmented-control`, `ui/toolbar` |
| App shell (VS Code-style) | `layout/app-shell`, `sidebar`, `sash` (drag-to-resize divider), `global-header`, `breadcrumb-trail` + `breadcrumbs.ts` (route map), `page-header`, `account-menu`, `auth-layout`, `shell-context` (entity names for breadcrumbs), `nav-items` |
| Global search | `search/global-search`, `search-result-parts`, `quick-actions` |
| Brand | `brand/attest-logo` (A mark with tick crossbar), `brand/attest-loader` (animated draw-in loader), `src/app/icon.svg` (favicon) |
| Theme | `theme/theme-provider`, `theme/theme-toggle` |
| Domain | `common/EmptyState`, `runs/RunStatusBadge`, `runs/StepScreenshots`, `test-cases/*`, `suites/*`, `projects/*` |

| shadcn aliases | `--secondary`, `--muted`, `--accent` (= state-active), `--input`, `--sidebar-*`, `--radius` (0.5rem) | | |

Contrast (WCAG AA, measured): white on primary 16.8:1 (light) / 6.9:1 (dark); brand-accent on surface 6.9:1 / 6.6:1; coral on its soft badge 4.6:1 / 4.9:1; muted text on surface 6.1:1 / 5.8:1; ring vs background ≥ 5:1.

Rules: no hard-coded colours in components; dark mode only through `[data-theme=dark]` tokens; run results use `pass` (brand blue) and `destructive` (coral), never green; KPI numbers stay in `--foreground` (status shows as a dot or a delta pill); use `text-brand-accent` for links (never `text-brand` for text).

## Inspiration and references (design ideas only, no code copied)

- **Modal.com, Linear, Vercel**: overall density, layered greys, page header structure, function-page layout for the test-case detail page.
- **VS Code**: flat shell with full-height 1px dividers and a draggable sash.
- **Salesforce**: global search with a scope picker, grouped results and recent items.
- **tweakcn** (tweakcn.com): the shape of the theme token block (shadcn variable names), so themes can be swapped by pasting a new token set.
- Theme, name and logo options were explored on preview pages before choosing: "Deep twilight × black" (later refined to "Dawn blue × charcoal"), the name **Attest**, and the A-with-tick mark.

## Storybook

Stories live in `src/stories/TestFlow/` (UI, Common, Brand, Dashboard, Suites, Search, Layout). Run with `npm run storybook` (port 6006). There's a light/dark toolbar toggle. Every reusable primitive should have a story covering default, hover/focus, disabled, loading, error and empty states (CLAUDE.md).

## Adding a component

1. Check whether `src/components/ui/` already has it.
2. If shadcn has it: `npx shadcn@latest add <name>`, fix any `from "cn"` import, then theme it with our tokens (no raw colours).
3. Icons: Lucide only. Charts: Recharts with `--chart-*` tokens. Tables: `DataTable`. Toasts: `toast` from Sonner.
4. Add a Storybook story.
